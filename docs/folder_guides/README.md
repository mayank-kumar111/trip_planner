# Folder Documentation Map

## Executive view
Every meaningful source/configuration directory is expected to contain a local `README.md` explaining purpose, responsibilities, inputs/outputs, dependencies, and impact. Generated/vendor trees are documented as exceptions where appropriate.

## Documentation convention
A directory README should answer:
1. What belongs here?
2. Which files are responsible for what?
3. What enters and leaves the directory?
4. Which dependencies/trust boundaries matter?
5. What can break if this directory changes?

## Repository areas
| Area | Purpose |
|---|---|
| `app/` | product UI, pages, and API routes |
| `components/` | shared UI |
| `context/` | client application context |
| `convex/` | persistence/backend functions |
| `hooks/` | reusable hooks |
| `lib/` | domain/provider/security modules |
| `tests/` | regression tests |
| `public/` | static assets |
| `.github/` | CI automation |
| `docs/` | human and technical documentation |

## Generated/vendor exceptions
`convex/_generated/` is generated by Convex and must not be manually edited. `node_modules/` is dependency-managed and is not part of the repository documentation contract.

## Coverage policy
The CI documentation check verifies required top-level documentation surfaces and configuration registries. New source directories should receive a local README as part of the same change; the folder guide can then be updated to reflect the new area.
